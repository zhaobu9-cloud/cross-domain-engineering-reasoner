# 开源项目参考卡

编号：〔P01〕  
检索阶段：〔本领域 / 跨域后，关联路线编号〕  
核查日期：〔实际日期〕

| 字段 | 内容 |
|---|---|
| 项目与规范仓库链接 | 〔实际核实的完整 URL；未核实不猜〕 |
| 原始问题 / 所属领域 | 〔来源内容〕 |
| 与本工程的对应关系 | 〔目标任务或关键子问题，不仅同一个行业〕 |
| 相关性类型 | 〔任务级 / 关键子问题级 / 通用基础库 / 非实现线索〕 |
| 已核实实现 | 〔作者声明、代码查看分别写；源码位置与版本/ref〕 |
| 可借用模块 | 〔已查路径、函数或接口；未知写尚未定位〕 |
| 复用层级 | 〔整体基线 / 独立模块 / 算法实现 / 接口或格式〕 |
| 输入 → 输出 | 〔格式、单位、数据语义、依赖条件〕 |
| 需要补齐或修改 | 〔与目标工程的差异、硬约束适配〕 |
| 开源状态与许可 | 〔许可证原文位置；待核实组件、依赖/权重/数据范围〕 |
| 维护和复现材料 | 〔实际查看的 release/commit/归档状态；样例/测试/依赖〕 |
| 本次执行状态 | 〔未运行 / 已复现何种样例 / 工程验证及范围〕 |
| 排序理由 / 排除理由 | 〔不以 Star 数代替；不声称可以直接生产使用〕 |
| 最小验证动作 | 〔对照、观测、失败条件、授权边界〕 |
| 证据来源 | 〔与上述具体事实逐项对应的来源〕 |

跨域项目额外填写：

`本工程子问题〔〕 → 来源结构〔〕 → 方法〔〕 → 本项目模块〔〕 → 必须改造〔〕 → 最小否证试验〔〕`

若代码、许可或关键能力无法核查，保持“候选待核实”；不要在这张卡中补造。
